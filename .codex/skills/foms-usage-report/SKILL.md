# FOMS 사용 현황 보고서

Datadog 근거를 임원이 처음 읽어도 판단할 수 있는 한국어 단일 HTML 보고서로 만든다. 이 스킬의 템플릿은 디자인·구성을 재사용하며, 과거 계정·숫자·날짜를 재사용하지 않는다.

## 입력과 범위

- 요청이나 대화에 확정된 기간·집계 결과·배송 수가 있으면 그대로 사용한다. 새 조회가 필요한지, 기존 자료 편집인지 구분한다.
- 기간이 없으면 최근 완료된 7일을 KST로 정하고 알린다. 요청한 과거 보고서를 오늘까지 자동 연장하지 않는다.
- 사용자 활동은 `foms-fe / prod`, 관리자(`usr.id:1`) 및 사용자 미식별 이벤트 제외가 기본이다. 서버 변경 이벤트는 `mario / prod` 전체이므로 관리자 제외 여부를 사용자 활동과 별도로 표시한다.
- 보고일은 현재 KST 날짜, 데이터 마감일은 실제 조회 종료 시각이다. 날짜만 고치라는 요청에는 데이터를 재집계하지 않는다.
- 배송 물량이 미제공이면 사용자 활동·이벤트 실적 보고서부터 만든다. 비율은 생략하거나 미산출로 표시하고, 필요한 분모의 출처를 설명한다.

## 근거 수집

새 데이터를 조회할 때 Datadog 플러그인 MCP를 사용하고 도구의 도메인 가이드를 먼저 읽는다. 조회법과 지표 의미는 [references/metrics-and-queries.md](references/metrics-and-queries.md)를 참고한다. MCP가 없는 환경에서 임의의 과거 숫자나 대체 인증 경로를 만들지 않는다. 이미 제공된 자료로 작성할 수 있는 부분은 진행한다.

- 집계 도구로 사용자·날짜·이벤트별 횟수와 `count` 합계를 구한다. 원시 표본으로 전체 합계를 추정하지 않는다.
- 조회 기간과 최초 관측 기록을 분리한다. 요청 시작일이 수집 시작일이라는 뜻은 아니다.
- 조회 이벤트가 특정 날짜에만 존재하면 사용자별 비교가 불완전함을 밝힌다. 변경 기록이 없고 클릭만 있는 계정을 미사용으로 판정하지 않는다.
- 서버 로그와 RUM을 대조할 때 동일 KST 구간으로 맞추고 실행 횟수와 대상 수를 각각 비교한다. 검증된 날짜·종류만 일치한다고 쓴다.
- 사용자 제공 이미지·SQL 결과는 출처와 날짜 기준을 보존한다. 실행하지 않은 SQL이나 검증하지 않은 필터를 실행·검증한 것처럼 표시하지 않는다.

## 임원용 구성

[assets/report.html](assets/report.html)을 복사해 사용한다. `{{...}}` 슬롯은 실제 자료로 채우거나 불필요한 블록을 제거한다. HTML 데이터 삽입 시 사용자명·라벨·URL 등을 올바르게 이스케이프한다.

1. **첫 화면:** 근거로 확인된 결론 한 문장과 핵심 수치 최대 3개. 예: 사용 확인 계정 수, 변경 업무 수행 계정 수, 주요 날짜의 작업량. 분모가 없는 ‘도입률’은 만들지 않는다.
2. **사용 범위:** 실제 사용 확인 계정과 변경 업무 계정을 구분한다. 계정 수를 실인원으로 단정하지 않는다.
3. **업무 활용:** 기본 그래프는 집품 설정 변경·포장순번 생성 두 항목만 표시한다. 배송 분모가 있으면 물량 대비 비율, 없으면 대상 수를 표시한다. 의미를 숫자 옆 한 줄로 설명한다.
4. **사용자별 업무 현황:** 기본 열은 `사용자 / 집품 설정 변경 대상 수 / 포장순번 생성 대상 수`. 두 값 모두 각 성공 이벤트의 `count` 합계다. 변경 성공 종류를 모두 합친 배송건 열은 기본으로 두지 않는다.
5. **보고 판단:** 현재 확인한 활용 수준과 다음 확인 사항을 짧게 적는다. 전환율·생산성·성과를 클릭이나 반복 변경 수에서 추론하지 않는다.
6. **부록:** 클릭 순위, 일자별 원천 집계, 사용자별 두 이벤트의 실행 횟수·대상 수, 집계 기준·출처 링크. 본문에 영문 이벤트명이나 내부 코드명을 노출하지 않는다.

사용자 요청이 이 구성보다 구체적이면 요청을 우선한다. 조회·엑셀·그리드 설정 이벤트는 수집 진단에 쓸 수 있지만 기본 사용자별 변경 실적 표에는 섞지 않는다.

## 수치 표현

- ‘집품 설정 변경 대상 수’와 ‘포장순번 생성 대상 수’처럼 작업·단위를 드러내는 이름을 쓴다.
- 동일 배송의 반복 변경과 기능 간 중복이 포함된 수는 고유 배송 수가 아니다. 집품 제외도 집품 설정 변경에 포함된다.
- 생성일 배송 수와 처리일 이벤트 수를 나눈 값은 **당일 배송 물량 대비 작업량**이다. 배송 처리율 또는 ‘FOMS 사용률 90%’로 바꾸지 않는다. 100% 초과도 숨기거나 상한 처리하지 않는다.
- 전체 대상 계정 수를 검증한 경우에만 `활동 계정 / 대상 계정` 사용자 도입률을 산출한다.
- 결측·미수집·미적용은 `—`와 사유로 표시한다. 확인된 0과 구분한다.

## 결과 작성·검증

- 외부 폰트·CDN 없이 동작하는 단일 HTML, slate 계열 색상, 반응형 표, 인쇄/PDF 저장 버튼을 유지한다. 날짜를 여러 위치에서 일관되게 갱신한다.
- 기존 보고서 수정이면 해당 파일을 편집한다. 신규 파일은 사용자 지정 경로, 없으면 로컬 보고서 폴더에 `FOMS-사용현황-보고서-YYYYMMDD.html`로 저장한다.
- 사용자별·일자별·이벤트별 합계를 총계와 대조한다. 비율을 재계산하고, 분자·분모·기간·관리자 조건을 확인한다.
- 모든 슬롯이 채워졌는지, 영문 이벤트명이나 이전 보고서 값이 남았는지 확인한다. 가능한 브라우저 렌더러로 데스크톱·모바일 가로 넘침과 표 가독성을 검사한다. 화면 확인을 못 했으면 명시한다.
- 결과 파일 링크와 데이터 기준 시각을 전달한다. 브라우저 열기는 요청받았을 때 실행한다. 생성은 게시·배포·메시지 전송·Git 커밋을 뜻하지 않는다.
